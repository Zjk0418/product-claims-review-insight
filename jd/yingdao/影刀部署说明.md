# 京东评价采集：影刀调用说明

## 文件用途

- `JDD_京东评价采集_影刀版.py`：完整、自包含且兼容影刀 Python 3.7 的模块，负责采集和飞书读写。
- `requirements.txt`：影刀 Python 环境需要安装的两个第三方包。

## 影刀配置

1. 在影刀应用的“流程”面板右上角选择“新建 Python 模块”。
2. 模块命名为 `JDD_京东评价采集`。
3. 保留影刀自动生成的顶部代码，将 `JDD_京东评价采集_影刀版.py` 的全部内容粘贴到它们下方并保存。
4. 在影刀“Python 包管理”中确认已有 `requests==2.31.0`、`websockets==11.0.3`。
5. 在主流程添加“调用模块”，选择模块 `JDD_京东评价采集`、函数 `collect`。
6. 给参数 `date_value` 传入日期，例如 `2026-08-16` 或 `2026/08/16`。
7. 将返回值保存为变量 `采集结果`，根据 `采集结果["status"]` 分支处理。

不要调用 `main`，不要使用“调用流程”；只使用“调用模块”并选择函数 `collect`。

写入口径：`评价数` 保留 `10万+` 等页面文本；`好评率` 写完整页面文案，例如 `超99%买家赞不绝口`，不再只写 `99%`。

采集策略：每批 20 个 SPU 优先调用批量接口；批量失败或缺失的 SPU 再逐条调用签名接口。只有签名接口明确返回登录、验证码或风险页时才设置 `needs_manual_verification=true`；普通超时或接口异常记入 `failed_spus` 并返回 `partial`。

登录预检：每次正式采集前，模块会检查专用 Chrome 中的京东登录状态。状态可用才开始请求评价接口；未登录、Cookie 过期或进入风险页时，模块会自动切换到京东扫码登录页，截取当前登录页面，并通过飞书机器人把文字和截图发给代码中配置的手机号对应员工。

扫码等待：发送提醒后，当前 `collect` 调用不会结束，而是最多阻塞等待 3 分钟。程序每 3 秒检查一次登录状态；检测到扫码登录成功后，自动返回商品页并继续本次采集，不需要重新运行影刀任务。如果 3 分钟仍未登录，才返回 `blocked` 和 `needs_manual_verification=true`，同时保留浏览器；此后扫码完成可按相同日期重跑。

浏览器收尾：正常完成、无目标记录或普通异常后，模块会通过 DevTools `Browser.close` 自动关闭监听 9222 端口的专用 Chrome，不会按进程名关闭普通 Chrome。如果 `needs_manual_verification=true`，浏览器会暂时保留，方便用户扫码或验证；同日期重跑成功后再自动关闭。

## 状态

- `complete`：采集、写入完成。
- `blocked` 且 `needs_manual_verification=true`：3 分钟等待期间未完成登录；浏览器仍保留，登录后可传同一日期重新执行。
- `no_target_records`：飞书中没有该日期的 SPU 记录。
- `partial`：部分 SPU 失败，可传同一日期重新执行。
- `blocked` 且 `needs_manual_verification=false`：程序、权限、网络或环境异常。

## 本地目录的含义

`jd/yingdao` 只是代码交付包。代码粘贴并保存进影刀后，不再依赖本目录，也不要求保留固定项目路径。

## 飞书密钥配置

影刀源码不再包含飞书密钥。部署到机器人电脑前，需要配置 `jd/.env.example` 中列出的系统环境变量；本地调试时也可以把填写好的 `.env` 放在影刀模块文件所在目录或其上一级目录。不要把真实 `.env` 粘贴进影刀源码或上传到代码仓库。

程序不生成采集结果、状态或断点文件。为了让京东登录状态能够跨任务保留，Chrome 自身仍会在机器人电脑的以下动态位置保存浏览器资料：

```text
%LOCALAPPDATA%\JDD_京东评价采集\chrome-profile
```

代码中没有用户名、盘符或固定电脑路径；每台电脑会自动使用自己的 `%LOCALAPPDATA%`。更换机器人电脑后需要重新登录京东一次。
